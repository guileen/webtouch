# Stage 3 · 下一代自适应通用交互引擎：演进白皮书与跨越式执行计划

> **来源**：2026-09-25 用户 `[State: E]` 表（原文）。

> **核心定义**：通过「意图族谱系泛化（Intents Expansion）→ 局部对称拓扑蒸馏（Pair-Skeleton Distillation）→ 金库隔离的人机交接环（Vault-Handoff HIL）→ 离线对抗回放放行（G-PROOF Gating）」四阶闭环，跳出单一爬虫式采集的窄巷，将系统从「针对单一搜索框的盲测工具」升维为「兼具全域零样本通用交互理解、本地凭据安全隔离与人机无缝接力的工业级自主 Agent 决策内核」。

## 二、阶段一：意图谱系爆发与 500+ 异构高熵语料库

### 2.1 破除单一意图偏置（激活 `INT-225`）

此前采集集中于 `input:search` 与 `click:Documentation`，模型可能退化为「关键词匹配器」。必须引入 6 大核心意图族，覆盖现代 Web 交互的完整基底空间：

| 意图族标识 | 语义目标 | 典型正样本模式 | 核心负样本混淆源 |
| --- | --- | --- | --- |
| `input:search` | 页面内容检索 | 顶部搜索栏、居中搜索框、带放大镜 combobox | 订阅邮箱输入框、表单字段 |
| `click:nav_doc` | 知识与文档导航 | 顶部导航 Docs、侧边栏 API、Guide 链接 | 版权链接、外部推广链接 |
| `click:login_entry` | 寻找用户鉴权入口 | Sign In、Log In、登录、用户头像图标按钮 | 注册按钮、找回密码、第三方授权 |
| `click:signup_entry` | 寻找注册入口 | Sign Up、Register、免费体验、Get Started | 登录链接、价格方案选购 |
| `input:form_field` | 表单关键字段定位 | 邮箱输入、用户名、搜索过滤器 | 搜索框、验证码输入框 |
| `click:submit` | 动作提交确认 | Submit、Search 确认、Confirm、主操作按钮 | Cancel、重置、返回上一步 |

### 2.2 采样空间熵控与物理防线

- **域名多样性配额**：总目标 500 条样本，覆盖独立二极域必须满足 `N_domain ≥ 450`；**单域名样本数上限 `N_sample ≤ 2`**。
- **物理守护延续**：调度器 `wt-batch-scheduler.sh` 维持每 8~10 站主动重置；自建 Chrome 独立 Profile 进程随跑随清；**禁止触碰宿主 9222 端口**（`CON-217`）。
- **候选空集重试兜底**：严格执行已上线的轻量重试（`≤ 2 次 × 400ms`），保障 CSR 站点提取骨架时的物理完备性。

## 三、阶段二：新一代轻量对偶蒸馏器研发（`pair_skeleton_distiller`）

历史废弃的 `trace_distiller.py` 强依赖整页 DOM 与不存在的代码接口，已物理归档（`INT-217`）。本阶段独立建立现代轻量级蒸馏内核。

输入特征抽取（`episode.v1`）：

- **空间张量**：`[x_norm, y_norm, w_norm, h_norm, aspect_ratio]`
- **语义张量**：`One-Hot(Tag) ⊕ One-Hot(Role) ⊕ TruncatedTextHash(32)`
- **拓扑图谱**：1-hop 邻居矩阵 `[Parent, Children, Siblings]`（至多 8 节点）

数据流：特征抽取 → 多层感知器拓扑投影层（MLP / Graph Interaction Layer）→ 标量相关度打分 `s = f_θ(v)` → 对偶相对排序损失（Pairwise Margin Ranking Loss）。

### 3.1 数学建模与损失函数

对任意样本帧，正样本（Ground Truth）特征向量为 `v⁺`，视口内全部对称负样本候选集合为 `{v⁻₁, …, v⁻_K}`；打分函数 `f_θ: ℝ^d → ℝ`。采用带自适应边界的**对偶边缘排序损失**：

- `γ > 0` 为几何隔离裕度（Margin Parameter，初始 `1.0`）；
- 当且仅当正样本预测分**高于所有负样本至少 `γ`** 时，损失梯度归零；
- 负样本间完全解耦，计算复杂度降至 `O(K)`，支持毫秒级单帧反向传播。

### 3.2 交付物硬性验收指标

- **模型体积极致约束**：ONNX 权重文件体积严格 `≤ 10 MB`。
- **CPU 极速前向推理**：单核 CPU 上单帧（含 64 候选节点）端到端打分延迟 `≤ 15 ms`。
- **特征解析零容忍**：完全对齐 `episode.v1`，只依赖已落盘的 1-hop 骨架与 BBox，**严禁反向索取整页 DOM**。

## 四、阶段三：安全金库协同与交互接力状态机（Vault & Handoff HIL）

把「找登录入口、调用本地金库填入、遇验证码挂起交接用户」做成工业级混合自主状态机（Mixed-Initiative State Machine）：

| 状态 | 名称 | 行为 |
| --- | --- | --- |
| S0 | 初始探索与定位态 | 识别并点击登录/注册入口 |
| S1 | 局部表单投影态 | 识别账号/密码输入框 |
| S2 | 本地安全金库注入（Local Vault Bridge） | 安全密钥环/Keychain →（脱敏通道）→ 内存一次性注入 →（零日志留存）；**`CON-212` 物理红线：密码绝对不入 Episode 快照，严格打码屏蔽** |
| S3 | 正常提交状态 | 点击 Submit 按钮 |
| S4 | 人机接力挂起态（Handoff） | 弹出桌面级系统提示；挂起上下文等待用户；用户在宿主浏览器完成滑块/2FA |
| S5 | 会话恢复与侧载持久化 | 复用当前 Context 或落盘至 Chrome Profile；Agent 恢复自适应通用决策链路 |

### 4.1 详细状态转移契约

- **S0 → S1（入口识别）**：模型在首页以 `click:login_entry` 意图执行高置信度点击，监听 URL 变更与 DOM 沉淀事件。
- **S1 → S2（金库挂接）**：定位 `type="password"`、`autocomplete="current-password"` 或语义为密码的节点；触发 OS 原生安全存储接口（macOS Keychain 或本地加密 SQLite 凭据库）；**`CON-212` 绝对安全红线**：凭据由浏览器自动化驱动直接注入，期间快照提取器强制执行 `[VAL_MASKED]` fail-closed 拦截，任何密码明文/哈希绝不写入 `episodes.jsonl`。
- **S2 → S4（防御感知与人机接力）**：触发判定＝检测到 iframe 注入的 hCaptcha / reCAPTCHA / 极验节点，或页面返回 403/429 挑战页；执行动作＝立即终止盲目点击、进入挂起保护态、向外部终端或通知中心发出 `WAIT_HUMAN_INTERVENTION [REASON: CAPTCHA_DETECTED]`；**安全锁**＝人工接力期间所有自动化键鼠驱动物理卸载，防止与用户真实操作产生事件冲突。
- **S4 → S5（无缝接棒）**：周期性探测页面 Cookie 域变动或跳转后 URL（如进入含 `/dashboard`、`/home` 或已无鉴权表单的页面）；确认通过后保存该 Profile 状态，Agent 重新激活常规模型推理。

## 五、阶段四：全域对抗回放（G-PROOF）与 T-3 决策带物理穿透

模型训练完成后，坚决恪守 `CON-218`，执行严苛离线对抗验证方可放行接入主决策带。

### 5.1 G-PROOF 离线对抗回放矩阵

- **测试数据集**：从 500 条样本中随机抽取 100 条作为 Hold-out 验证集，且**测试集域名绝对不得出现在训练集**（Zero-Leakage Domain-wise Split）。
- **回放评测维度**：
  - Top-1 命中率（Precision@1）：模型打分最高的候选节点恰好为 Ground Truth 的比例。
  - Top-3 召回率（Recall@3）：Ground Truth 落在前 3 名高分候选中的比例。
  - 对抗鲁棒性（Adversarial Robustness）：页面存在相似干扰项（导航栏同时 5 个并列链接、多个输入框）时，正样本与次优候选打分差值是否满足 `Δs > 0.5γ`。

### 5.2 T-3 门禁放行硬指标（Gate Passage Criteria）

| 验证项 | 门禁阈值 | 达标前状态 | 达标后状态 |
| --- | --- | --- | --- |
| 离线 Precision@1 | `≥ 90.0%` | 仅影子通道运行（Scorer 恒为 `nil`） | 允许介入主决策链路 |
| 离线 Recall@3 | `≥ 98.0%` | 必须使用规则兜底 | 允许模型接管首选路由 |
| 陌生二极域实测 | 连续 20 站零失误 | 拦截高危操作 | 解除保守限速策略 |
| 凭据泄露审计 | 违规命中数 `= 0` | 熔断中断全链 | 放行自动填充链路 |

## 六、科学证伪体系与评测协议（Falsification Protocol）

**假设 1：1-hop 局部骨架足以支撑全网交互意图识别。**
理论前提：用户操作按钮时的决策依据主要来自按钮自身属性及其紧邻上下文（父容器、相邻兄弟文本），不需要整页完整 DOM。
证伪实验：在 100 个异构测试页面上，分别运行「1-hop 局部骨架模型」与「全量全局 DOM + LLM」。
判据：若 1-hop 模型 Precision@1 较全局模型落后幅度**超过 15%**，则证伪；需升级为 2-hop 路径或引入视口全局空间注意力。

**假设 2：跨域 UI 组件流形具备强通用性（跨域零样本可泛化）。**
理论前提：在 Wikipedia、GitHub 上训练出的元素排序模型，在从未见过的日文个人博客或企业内网系统上依然成立。
证伪实验：域留一交叉验证（Leave-Domain-Out CV）——用欧美主流英文站训练，直接在 50 个非英语、非主流开源框架自建站上推演。
判据：若跨语言/跨框架 Top-1 命中率跌落至 **< 60%**（甚至劣于启发式规则基线），则证伪；证明模型过拟合英文字符哈希或特定主流框架 DOM 惯例，必须重构特征归一化层。

## 七、已知架构缺口、物理瓶颈与防线边界

| 暗礁 | 缺口描述 | 边界策略 |
| --- | --- | --- |
| 复杂 Canvas / WebGL 虚拟化 | 界面完全绘制在单个 `<canvas>` 或 WebAssembly 渲染的站点，DOM 树为空，`episode.v1` 骨架彻底失效 | 定义为**非骨架覆盖域**，绝不强行解析，直接退避至外部视觉大模型（VLM）坐标预测通道 |
| 跨域 Iframe / 深层 Shadow DOM 隔离 | SSO 表单嵌套在跨域 Iframe 内，同源策略导致宿主无法穿透注入 1-hop 快照 | 在快照提取器中增强对 `contentDocument` 与 `shadowRoot` 的递归穿透遍历能力 |
| 反自动化指纹对抗（Bot Detection）的时变漂移 | Headless Chrome 高频自动化易泄漏环境指纹（`navigator.webdriver`、WebGL 特征差异），触发 Cloudflare / Akamai 强拦截 | 严格遵守 Handoff 机制：识别到对抗风控立即把控制权交还用户真实浏览器，**绝不投入精力在端侧对抗逆向风控** |

## 八、前沿突破悬赏任务书（Bounty Tasks）

- **【BOUNTY-01】极致轻量化 GNN/Transformer 骨架排序器**
  目标：替代标准 MLP 级联网络，设计能直接感知图同构（Graph Isomorphism）的微型网络（参数量 `≤ 50 万`）。
  挑战：单 CPU 核心完成 1-hop 局部子图的图注意力聚合，内存占用 `< 20MB`。
  验收红线：跨域验证集 Top-1 命中率突破 `95.0%`，单步打分耗时严格 `< 10 ms`。
- **【BOUNTY-02】零侵入无感会话侧载器（Zero-Invasive Session Side-loader）**
  目标：实现无状态进程与宿主持久化环境的解耦协议。
  挑战：在不锁定用户日常 Chrome 数据目录的前提下，秒级安全提取特定域名的有效授权凭据（Cookies & LocalStorage），并在隔离的临时 Headless 容器中无缝还原已登录态。
  验收红线：全流程无须重启宿主主浏览器，对用户现有工作环境 `0` 影响、`0` 状态污染。
- **【BOUNTY-03】通用表单意图槽位反向推定算法（Inverse Intent Slot Filling）**
  目标：面对数十个输入框的复杂注册/申请页，无需人工预先指定意图，仅凭页面局部语义自适应推定每个输入框应填充的信息类型（如「姓」「名」「公司」「邮编」）。
  挑战：仅依赖当前提取的 32 字符截断语义文本及邻近 Label，零外部网络调用实现端到端纯离线映射。
  验收红线：多字段复杂表单对号入座准确率 `≥ 92.0%`。

## 十、与既有红线的衔接（本仓登记时的对齐声明）

- **人机验证（CAPTCHA / 2FA / 风控）仍属真风险停止线**：阶段三的 S4 是**把控制权交还用户**，不构成「自动化破解验证码」；Agent 侧只做「识别 → 挂起 → 通知 → 轮询鉴权成功」，绝不下发任何绕过性操作。
- **凭据红线不变**：明文唯一出口仍是引擎本机对 `@vault:<名>` 解引用后直填；不进 argv/`ps`、不过 gRPC、不进日志、不进 Episode（`CON-212`）。
- **`T-3` 放行门不变**：`CON-218` 三重条件由本文 §5.2 量化为具体阈值；未达标前决策 Scorer 必须恒为 `nil`。
- **`CON-217` 不变**：宿主 9222 及其 Tab/Context 绝对只读，任何调度与看护脚本不得触碰。
