# Tier 1 候选质量量尺（T-11A 第二批 · 2026-09-23）

> **语料标签：合成集基线。** 本文所有数字来自合成 DOM 语料（`SEED=42`），
> 不代表真实站点表现。真实站点语料按站点留出 holdout 后另行报数。
> 定位：T-11A「量出现有算法资产的候选质量与分段耗时」的测量入口，
> 不是新算法，也不改出厂常量。

## 1. 结论（一句话）

在合成语料上，管线**没有检索问题、也没有排序问题**：候选池平均 4.66 个，
真身 100% 进入候选池，剪枝后仍有 98.6%；剩下的全部损失来自两处——拓扑剪枝
（−1.4%）与**身份门禁主动拒绝**（−8.6%，设计如此，用 miss 换掉 false heal）。
真正缺的是**能鉴别排序质量的语料**：真身秩分布只有 `{0: 7, 1: 493}`，
即「要么第 1、要么不在」，排序策略怎么改指标都不动。

## 3. 故障分段（n=500）

| 阶段 | 真身存活率 | 说明 |
| --- | --- | --- |
| L1 规则召回（文本命中） | 100.0% | **构造使然**：规则库由 case 语义本身生成，此列不是真实召回率 |
| 双通道门禁（文本 OR 结构+role 兼容） | 100.0% | 该语料上门禁的角色兼容分支惰性（见 §6） |
| 拓扑剪枝（`structDist ≤ 10`） | 98.6% | 唯一有损阶段，损失全部在 `tag_role` 家族的幽灵样本 |
| 排序选优 + 身份门禁（决策） | 90.0% | 与既有 `run_tier1.py` 的 `P_new=90.0%` 完全一致（交叉校验通过） |

候选规模：L1 池均值 4.66 → 剪枝后均值 **0.99**。
**推论**：进 ONNX 重排区的候选平均不到 1 个 —— 重排阶段在合成语料上基本无活可干。

## 4. 候选质量

| 指标 | 值 |
| --- | --- |
| recall@1 / @2 / @3 / @5 / @10 | 98.6% / 98.6% / 98.6% / 98.6% / 98.6% |
| MRR | 0.986 |
| 决策精度（top-1 + 身份门禁） | 90.0% |
| shortlist 纯度 plausible@1 | 90.0% |
| 假修复暴露 false_heal@1 / @3 | 0.000 / 0.000 |
| 真身秩分布 | `{0: 7, 1: 493}` |

recall@k 对 k 完全不敏感 + 秩分布只有 0/1 ⇒ **合成语料零排序难度**，无法用于
比较重排策略（含 ONNX 增广）。这是本轮的负面结论，也是去采真实语料的直接理由。

## 5. calibration / holdout

按 `case_id` 的 SHA-1 奇偶切分（确定性、实例不重叠；**不用奇偶序**——`tag_role`
幽灵样本恰好落在偶数 `si`，序奇偶切分会把两个子群整体分到两侧，制造假的分布差异；
切分后幽灵两侧为 4 / 3）。

| 口径 | calibration (n=252) | holdout (n=248) |
| --- | --- | --- |
| 出厂常量 `dth=5, prune=10` 决策精度 | 90.5% | 89.5% |
| 标定选出 `dth=0, prune=12` 决策精度 | 90.5% | 89.5% |

**标定点与出厂常量的决策精度完全相同**（calibration 与 holdout 都相同）：
标定只换来 recall/MRR 的名义提升（把身份门禁必然拒绝的幽灵样本留在短名单里），
代价是短名单从 0.99 涨到 2.0。结论：**该语料不足以标定阈值**，出厂常量无需改。

## 6. 分段耗时（单机墙钟 · 单次运行示例）

| 阶段 | 总耗时 | 每 case |
| --- | --- | --- |
| L1 规则匹配（`matcher.MatchNode`） | 4.09 ms | 8.2 µs |
| 文本通道 SimHash + Hamming | 5.21 ms | 10.4 µs |
| 结构通道 SimHash + Hamming | 40.29 ms | 80.6 µs |
| 门禁 + 拓扑剪枝 | 0.24 ms | 0.5 µs |
| 排序 + 选优 + 身份门禁 | 0.20 ms | 0.4 µs |

- 结构通道是**唯一的主导成本**（约 8× 文本通道；含逐祖先链遍历与属性白名单）。
- 本管线**不执行** probe / classifier / VLM 三段（无 Browser/CDP、无 ONNX 时跳过
  增广重排），因此这三段标为未测而非填数；时长随机器负载波动，不计入字节可回放口径。

## 7. 本轮修复与诚实边界

- **修复**：`drift_set.py` 的幽灵包装类名原先用**未播种的全局 `random`**
  （`make_page` 内 `random.randrange`），导致同 `--seed` 两跑字节不一致。
  已改为使用传入的 `rng`。修复后字节可复现，**指标不变**（修复前后
  `tier1_metrics.json` 逐字节相同）。
- `l1_recall = 100%` 是构造使然，不可当作真实召回能力。
- 该语料上门禁的 role 兼容分支惰性：把 Go 侧 `compat` 强置为 `true`，`candidates`
  与所有指标均不变（见 §8 MUT-B）。
- 身份门禁在决策阶段仍在起作用：把候选的 `role_compat` 强置为 `true`，决策精度
  从 90.0% 跳到 98.6% —— 提升是假的（那 8.6% 正是本应被拒绝执行的幽灵样本）。
